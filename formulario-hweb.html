01 · Contexto

Como funciona hoje e onde queremos chegar

O processo atual depende de comunicação manual, estrutura de pastas no Google Drive e documento Word. O resultado é bom, mas o caminho gera retrabalho e risco de erro.

⬤ Processo atual
Analista cria pasta manualmente no Google Drive por cliente
Cliente recebe documento Word modelo para preencher textos
Imagens enviadas sem validação de resolução ou formato
Analista organiza manualmente o conteúdo antes de produzir
Sem rastreabilidade de status da coleta por propriedade
Conteúdo chega fragmentado, exigindo reunião de alinhamento
⬤ Processo proposto
Formulário estruturado enviado ao cliente com link único
Campos com validação em tempo real — texto e imagem
Lógica condicional: só aparecem campos das seções que existem
Ao submeter, conteúdo é injetado automaticamente no Duda via API
Analista recebe notificação e revisa conteúdo já organizado
Log de status por propriedade disponível no sistema HSystem
⏱
Menos tempo de coleta
Elimina vai-e-vem de mensagens para corrigir imagens fora do padrão ou campos incompletos.
⚡
Analista começa produzindo
O conteúdo já entra organizado no Duda. O analista abre o editor e começa o site, sem montar estrutura.
📊
Visibilidade de processo
Cada propriedade tem status rastreável: aguardando envio, em revisão, aprovado, em produção.
02 · Solução

Arquitetura da solução

Formulário próprio embarcado no sistema HSystem, com backend Node.js responsável pelo mapeamento e integração com a API REST do Duda.

Stack tecnológica
🌐
Frontend — Formulário embarcado (HTML/CSS/JS ou React)
Multi-step com 6 etapas, lógica condicional por seções, upload de imagens com validação de resolução (mín. 1200×800px), tags de comodidades, categorias dinâmicas de acomodação.
⚙️
Backend — Node.js (Express ou Fastify)
Recebe o payload do formulário, valida, faz upload das imagens para o Duda, monta o JSON de conteúdo e chama a Content API. Gerencia retry automático, log por propriedade e notificação para o analista.
🔗
Integração — Duda Partner REST API
Autenticação Basic (API user:password). Endpoints utilizados: POST /content para textos e contatos, POST /resources/upload para imagens, e notificação interna após conclusão.
📦
Armazenamento — banco de dados HSystem
Cada envio cria um registro com: id da propriedade, site_name no Duda, status do envio, timestamp, campos preenchidos, lista de imagens enviadas e log de erros.
⚠ As credenciais da API Duda (user:password) devem ser armazenadas como variáveis de ambiente no backend. Nunca devem ser expostas no frontend ou em repositórios de código.
03 · Fluxo

Jornada completa do conteúdo

Do envio pelo cliente até o conteúdo disponível no editor do Duda para o analista iniciar a produção.

1
Analista cria o site no Duda e gera o link do formulário
O analista cria o site no Duda (obtendo o site_name), registra a propriedade no sistema HSystem e gera o link personalizado do formulário já vinculado a esse site. O link é enviado ao cliente por WhatsApp ou e-mail.
Responsável: Analista HWEB
2
Cliente preenche o formulário (6 etapas)
O cliente preenche identificação, contatos, seleciona as seções da propriedade, escreve os textos, cadastra as categorias de acomodação (com alerta de alinhamento HBOOK) e faz upload das imagens. O formulário valida campos obrigatórios e dimensão mínima das fotos antes de permitir o envio.
Responsável: Cliente
3
Backend processa o envio
O backend recebe o payload, valida integridade dos dados e executa as 4 chamadas à API Duda em sequência: (1) POST /content com textos e contatos, (2) upload da logo + atualização de logo_url, (3) upload das imagens em lote por categoria, (4) atualização de site_images com labels organizados. Em caso de falha em qualquer etapa, retry automático com 3 tentativas e log de erro registrado.
Responsável: Sistema (automático)
4
Notificação para o analista
Após conclusão dos uploads, o sistema envia notificação interna (e-mail ou card no sistema HSystem) com: nome da propriedade, link direto ao site no Duda, seções preenchidas e eventuais alertas de conteúdo. Status da propriedade muda para "Em revisão".
Responsável: Sistema (automático)
5
Analista revisa e inicia produção
O analista abre o editor do Duda e encontra todo o conteúdo já organizado na Content Library — textos em Business Data/Site Texts, imagens em pastas nomeadas por categoria. Aprova, solicita ajustes ao cliente ou inicia a produção diretamente.
Responsável: Analista HWEB

05 · Integração

API Duda — especificação técnica

Sequência de 4 chamadas executadas pelo backend após o cliente submeter o formulário. Autenticação Basic em todas as requisições.

ℹ Base URL: https://api.duda.co/api/sites/multiscreen/{site_name} · Autenticação: Authorization: Basic base64(user:password)
POST /content Chamada 1 — Textos e contatos
// Business data, location, social accounts e site_texts em uma única chamada { "business_data": { "name": "Nome da Propriedade" }, "location_data": { "phones": [ { "phoneNumber": "(00) 00000-0000", "label": "Telefone" }, { "phoneNumber": "(00) 00000-0000", "label": "WhatsApp" } ], "emails": [{ "emailAddress": "contato@exemplo.com", "label": "Contato" }], "address": { "streetAddress": "Rua Exemplo, 123", "city": "Cidade", "region": "UF", "postalCode": "00000-000", "country": "BR" }, "social_accounts": { "instagram": "handle", "facebook": "handle", "tripadvisor": "url-slug", "youtube": "channel-id" } }, "site_texts": { "about_us": "Texto sobre a propriedade...", "services": "Serviços e comodidades...", "custom": [ { "label": "localizacao", "text": "Texto da região..." }, { "label": "gastronomia", "text": "Texto do restaurante..." }, { "label": "lazer", "text": "Texto de lazer..." }, { "label": "eventos", "text": "Texto de eventos..." }, { "label": "acom_nome_1", "text": "Golden" }, { "label": "acom_desc_1", "text": "Descrição da categoria..." }, { "label": "acom_items_1", "text": "Cama king, Hidromassagem, Wi-Fi..." } ] } }
POST /resources/upload Chamada 2 — Upload da logo
// Passo 1: backend envia o arquivo para storage HSystem → obtém URL pública // Passo 2: POST /resources/upload com a URL (a API não aceita binário direto) [ { "src": "https://storage.hsystem.com.br/uploads/logo.png", "resource_type": "IMAGE" } ] // Resposta correta (campo é uploaded_resources[].new_url — não n_urls): { "n_failures": 0, "uploaded_resources": [ { "original_url": "https://storage.hsystem.com.br/uploads/logo.png", "new_url": "https://irp.cdn-website.com/.../logo.png", "status": "UPLOADED" } ] } // Em seguida, POST /content para atualizar logo_url: { "business_data": { "logo_url": "https://irp.cdn-website.com/.../logo.png" } }
POST /resources/upload + /content Chamada 3 — Imagens em lote por categoria
// Para cada categoria: upload → obter URL → adicionar em site_images // O label define a "pasta" que o analista verá no editor POST /content { "site_images": [ { "label": "Fotos da Propriedade", "url": "https://cdn.../img1.jpg", "alt": "" }, { "label": "Acomodações/Golden", "url": "https://cdn.../img2.jpg", "alt": "Suíte Golden" }, { "label": "Acomodações/Lake", "url": "https://cdn.../img3.jpg", "alt": "Suíte Lake" }, { "label": "Gastronomia", "url": "https://cdn.../img4.jpg", "alt": "" }, { "label": "Destino", "url": "https://cdn.../img5.jpg", "alt": "" } ] } // ⚠ O Duda não cria pastas via API — o label é a organização visual no editor // ⚠ Máximo 10 recursos por chamada — processar imagens em lotes de 10 com await entre cada lote // ⚠ label tem limite de 80 chars — garantir que "Acomodações/" + nome_categoria não ultrapasse
INT sistema HSystem Chamada 4 — Notificação interna
// Após todas as chamadas Duda concluídas com sucesso { "propriedade": "Nome da Propriedade", "site_name": "duda-site-id", "duda_url": "https://my.duda.co/home/sites/duda-site-id", "status": "aguardando_revisao", "secoes": ["gastronomia", "destino"], "n_categorias": 3, "n_imagens": 24, "timestamp": "2026-06-04T14:30:00Z" } // Status possíveis: aguardando_revisao → aprovado / pendencias / reprovado

Frontend — requisitos
✓ Multi-step com 6 etapas + progress bar
✓ Validação em tempo real por campo (blur)
✓ Validação de dimensão de imagem antes do upload (FileReader API)
✓ Lógica condicional: campos aparecem conforme toggles do step 3
✓ Categorias de acomodação dinâmicas (sem limite, renumeração automática)
✓ Bloqueio de avanço se campos obrigatórios não preenchidos
✓ Suporte a CDR convertido (cliente deve enviar como PNG/JPG)
✓ Múltiplos telefones/WhatsApp dinâmicos (mín. 1 obrigatório)
✓ Nomes de seções editáveis pelo analista (Etapa 3)
✓ Botão "Enviar conteúdo" bloqueado até termo de responsabilidade marcado
✓ Responsivo para mobile
Backend — requisitos
✓ Recebe payload multipart/form-data (textos + arquivos)
✓ Valida integridade antes de chamar a API Duda
✓ Sequência de chamadas: content → upload logo → upload imagens → site_images
✓ Retry automático: 3 tentativas com backoff exponencial por chamada
✓ Log estruturado por propriedade (site_name + timestamp + status por etapa)
✓ Notificação ao analista após conclusão (e-mail ou webhook interno)
✓ Credenciais Duda apenas em variáveis de ambiente (.env)
✓ Rate limit Duda: respeitar 100 req/min — processar imagens em fila
✓ Upload em lotes de máx. 10 recursos/chamada (limite da API)
✓ Storage intermediário: arquivos enviados ao HSystem antes do upload para o Duda (API aceita src URL, não binário direto)
✓ Resposta de upload: ler uploaded_resources[].new_url (não n_urls)
✓ label de site_images: máx. 80 chars — truncar se necessário
⚠
Atenção sobre CDR (CorelDraw): O Duda não aceita arquivos .CDR. O formulário deve orientar o cliente a exportar logos em PNG ou SVG antes do envio. Incluir mensagem explicativa no campo de upload da logo.
