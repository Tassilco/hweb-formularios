01 · Contexto

O Combo Starter e o processo de coleta

O modelo Combo Starter tem estrutura fixa de 4 páginas, tornando a implantação mais simples e rápida. O formulário reflete essa simplicidade — sem toggles condicionais, sem vídeo, com campos direcionados ao conteúdo que esse modelo realmente usa.

⬤ Processo atual
Analista cria pasta no Google Drive e envia documento Word ao cliente
Imagens enviadas sem validação de resolução ou formato
Analista organiza manualmente todo o conteúdo antes de iniciar
Sem distinção de coleta entre modelos — processo igual para todos
Retrabalho frequente para corrigir conteúdo fora do padrão
⬤ Processo proposto
Formulário específico para o Combo Starter, com link único por cliente
Campos alinhados às 4 páginas fixas — sem campos desnecessários
Conteúdo injetado automaticamente no Duda ao submeter
Analista abre o editor com conteúdo já organizado por seção
Validação de imagens e campos obrigatórios em tempo real
⚡
Implantação mais rápida
Estrutura fixa elimina decisões sobre seções — o analista sabe exatamente o que esperar ao abrir o editor.
🎯
Coleta direcionada
Sem campos de vídeo ou seções condicionais — o cliente preenche apenas o que o modelo realmente usa.
📦
Mesma base técnica
Reutiliza a mesma integração com a API Duda do formulário principal — sem infraestrutura adicional.
02 · Solução

Arquitetura da solução

Mesma base técnica do formulário HWEB completo — frontend multi-step, backend Node.js e integração via API REST do Duda — com payload simplificado para o modelo Combo Starter.

Stack tecnológica
🌐
Frontend — Formulário embarcado (HTML/CSS/JS ou React)
6 etapas: Identificação → Contatos → Seções → Textos → Quartos → Imagens. Páginas fixas (Home, Quartos, Destino, Contato) exibidas como confirmação — sem toggles. Pontos turísticos dinâmicos (mín. 3). Seção extra opcional que propaga para Textos e Imagens.
⚙️
Backend — Node.js (Express ou Fastify)
Recebe o payload, valida, faz upload das imagens para o Duda, monta o JSON de conteúdo e chama a Content API. Gerencia retry automático, log por propriedade e notificação ao analista. Payload mais simples que o formulário principal — sem campos condicionais.
🔗
Integração — Duda Partner REST API
Autenticação Basic (API user:password). Endpoints: POST /content para textos e contatos, POST /resources/upload para imagens. Sem campos de vídeo — o modelo Combo Starter não utiliza banner em vídeo.
📦
Armazenamento — banco de dados HSystem
Cada envio cria um registro com: id da propriedade, site_name no Duda, status do envio, timestamp, campos preenchidos, lista de imagens e log de erros. Identificado como "Combo Starter" no sistema.
⚠ As credenciais da API Duda (user:password) devem ser armazenadas como variáveis de ambiente no backend. Nunca devem ser expostas no frontend ou em repositórios de código.
03 · Fluxo

Jornada completa do conteúdo

Do envio pelo cliente até o conteúdo disponível no editor do Duda para o analista iniciar a produção do site Combo Starter.

1
Analista cria o site no Duda e gera o link do formulário
O analista cria o site no Duda com o template Combo Starter (obtendo o site_name), registra a propriedade no HSystem como modelo Combo Starter e gera o link personalizado. O link é enviado ao cliente por WhatsApp ou e-mail.
Responsável: Analista HWEB
2
Cliente preenche o formulário (6 etapas)
O cliente preenche identificação, contatos, confirma as 4 páginas fixas (podendo adicionar seção extra), escreve os textos das seções, cadastra as categorias de acomodação (com alerta de alinhamento HBOOK) e faz upload das imagens. O formulário valida campos obrigatórios e dimensões das fotos antes de permitir o envio.
Responsável: Cliente
3
Backend processa o envio
O backend recebe o payload, valida integridade e executa 3 chamadas à API Duda em sequência: (1) POST /content com todos os textos e contatos, (2) upload da logo + atualização de logo_url, (3) upload das imagens em lote por categoria e atualização de site_images com labels organizados. Em caso de falha, retry automático com 3 tentativas e log de erro registrado.
Responsável: Sistema (automático)
4
Notificação para o analista
Após conclusão dos uploads, o sistema envia notificação interna com: nome da propriedade, modelo (Combo Starter), link direto ao site no Duda, categorias de acomodação preenchidas e eventuais alertas. Status muda para "Em revisão".
Responsável: Sistema (automático)
5
Analista revisa e inicia produção
O analista abre o editor do Duda e encontra todo o conteúdo organizado: textos em Business Data/Site Texts, imagens em pastas por categoria. Com as 4 páginas já definidas no template, basta aplicar o conteúdo e ajustar o visual.
Responsável: Analista HWEB

05 · Integração

API Duda — especificação técnica

Sequência de 3 chamadas executadas pelo backend após o cliente submeter o formulário. Autenticação Basic em todas as requisições. Sem campos de vídeo — o modelo Combo Starter não utiliza banner em vídeo.

ℹ Base URL: https://api.duda.co/api/sites/multiscreen/{site_name} · Autenticação: Authorization: Basic base64(user:password)

Frontend — requisitos
✓ Multi-step com 6 etapas + progress bar
✓ Validação em tempo real por campo (blur)
✓ Validação de dimensão de imagem antes do upload
✓ 4 páginas fixas exibidas como itens não editáveis na Etapa 3
✓ Seção extra opcional — propaga campos para Etapas 4 e 6
✓ Pontos turísticos dinâmicos (mín 3, sem limite máximo)
✓ Categorias de acomodação dinâmicas (mín 1)
✓ Múltiplos telefones/WhatsApp dinâmicos (mín 1 obrigatório)
✓ Bloqueio de avanço se campos obrigatórios não preenchidos
✓ Botão "Enviar" bloqueado até termo de responsabilidade marcado
✓ Sem campos de vídeo (não utilizado no Combo Starter)
✓ Responsivo para mobile
Backend — requisitos
✓ Recebe payload multipart/form-data (textos + arquivos)
✓ Valida integridade antes de chamar a API Duda
✓ Sequência: POST /content → upload logo → upload imagens
✓ Retry automático: 3 tentativas com backoff exponencial
✓ Log estruturado por propriedade (site_name + timestamp)
✓ Notificação ao analista após conclusão com tag "Combo Starter"
✓ Credenciais Duda apenas em variáveis de ambiente (.env)
✓ Rate limit Duda: respeitar 100 req/min
✓ Upload em lotes de máx. 10 recursos/chamada (limite da API)
✓ Storage intermediário: arquivos HSystem → URL → Duda
✓ Resposta de upload: ler uploaded_resources[].new_url
✓ label de site_images: máx. 80 chars — truncar se necessário
⚠
CDR (CorelDraw) não suportado: O Duda não aceita arquivos .CDR. O formulário deve orientar o cliente a exportar logos em PNG, SVG ou JPEG antes do envio.
